# Arabic and English at Veelad

Veelad keeps its existing Express/MySQL backend and plain JavaScript frontend. English is the default. Public and dashboard routes use `/en/...` and `/ar/...`; both product pages refer to the same product ID, stock, artwork, price and order history. Production deployment remains a separate release; payments are unchanged.

## Interface translations

Interface translations live in `public/assets/locales/en.js` and `public/assets/locales/ar.js`. These are synchronous browser dictionaries so the frontend can render without a translation service or a new framework. `public/assets/i18n.js` owns locale selection and formatting.

Use `t('English source key', {name: value})` for interface text. Add matching keys to both dictionaries, using `{name}` placeholders instead of concatenating sentences. Escape untrusted values before inserting translated text into HTML. Keep IDs, category values, order state values, variant values, form field names and API routes stable; translate their displayed labels only. Product and artist content uses `localField(record, 'title')` or the corresponding field. Missing Arabic content falls back to the English value; administrators and artists can supply reviewed Arabic copy without duplicating the product.

English is required for a submitted design's title and description; Arabic fields are optional. Drafts may be incomplete. Tags have separate English and Arabic fields and search matches both languages. Category names are translated centrally.

For an additional language, add a dictionary, update the centralized locale allowlist/helpers, add route/SEO alternates and extend the browser and server tests. Do not add per-component language detection.

## Language selection and formatting

The header and dashboard have an accessible language button. Switching preserves the route, product/artist ID and query parameters. Cart and saved designs use the same state in both languages. Text fields, options and uploaded artwork are retained when switching an open editor. The choice is stored in localStorage and a first-party language cookie; signed-in accounts also save their dashboard preference on the server. An explicit language in the URL takes precedence. Root navigation redirects to the remembered language, otherwise English.

Use the shared `localDate()`, `localNumber()` and currency helper for interface formatting. Arabic dates use the Gregorian calendar so order dates remain consistent. Set the optional environment variable `NUMERAL_SYSTEM=latn` (default) or `NUMERAL_SYSTEM=arab` for Arabic-Indic numerals. The server passes the validated choice to the shared formatting helpers; stored numeric values remain unchanged. A browser-only `window.VEELAD_NUMERAL_SYSTEM` override is available for preview/testing.

## RTL and typography

`setLanguage()` sets `<html lang="ar" dir="rtl">` or `<html lang="en" dir="ltr">`. Styles use logical inline spacing and positioning. Flex/grid follow document direction; only directional arrow icons mirror. Logos, photos, uploaded designs, product mockups and artwork are not flipped. Email addresses, passwords and English editing fields retain LTR direction; Arabic content fields are explicitly RTL.

`public/assets/i18n.css` defines font and line-height tokens. Arabic uses a subset of IBM Plex Sans Arabic, renamed Veelad Arabic to respect its reserved font name, with comfortable body leading and no letter spacing. English uses DM Sans and Manrope. Fonts are self-hosted WOFF2 subsets with `font-display: swap`, Arabic shaping tables retained, and SIL Open Font License notices under `public/assets/fonts/`. There is no font hotlink or runtime font-provider dependency. Thmanyah is the stylistic reference requested by the owner; its site was inaccessible from the development environment. These freely licensed fonts are an independent choice, not copied proprietary assets.

## SEO and checks

Each language has its own canonical URL, localized page metadata, `hreflang` alternates and sitemap entries. Structured product data keeps the same SKU and commercial values. Staging remains `noindex`; private dashboards, previews, reset links, checkout and tracking links are not indexed. Legacy English URLs and bookmarks remain supported.

Run `npm run check`, `npm test`, and `npm run test:ui` with the existing local database setup. Bilingual browser tests cover language switching, state preservation, RTL public pages and administrator screens, bilingual design submission, private original download, publication and Arabic search. Server tests cover localized SEO and authorization. Chromium mobile emulation supplements desktop testing; final acceptance on an actual iPhone/Safari is still useful.

The Arabic brand spelling is assumed to be **فيلاد**; the existing Latin logo remains unchanged.

## Copy review

Arabic interface copy uses modern, concise wording. Product copy and confirmed manufacturing/delivery/return terms must be reviewed by the store before publication. Unsupported SVG/PDF files are not advertised as accepted; the implemented upload formats are PNG and JPEG. The product-placement preview is illustrative and is not a production proof.
