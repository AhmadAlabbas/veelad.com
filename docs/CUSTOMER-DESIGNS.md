# Customer design studio

Customers can create private, made-to-order items at `/en/create` and `/ar/create`. They sign in, select an available product and option, upload PNG/JPEG artwork or create text-only artwork, adjust its placement, review the provisional preview, and add it to their bag. The same upload can be placed on another enabled product without uploading again. Personal designs never become public product listings.

## Administrator setup

In **Administrator → Products → Edit product**, enable **Allow customers to create their own design on this product**, then save. Only active, in-stock, explicitly enabled products are offered. Existing products remain disabled by default. Use suitable blank-product listings with accurate names, prices, options, stock and specifications; the preview uses the blank template for the category and replaces the catalog artwork with the customer's own artwork. Enabling customization does not change the existing product listing or its normal purchases.

The existing product's retail price, options and shared stock apply. No prices, supplier measurements or print costs are invented by the studio. Personal orders carry no artist attribution or royalty, because they contain the customer's artwork. Ordinary purchases retain the artist and royalty. Artists cannot enable this setting through their submission API. Check your fulfillment costs before enabling a product.

## Customer workflow

1. Open **Create your own** in the category navigation or mobile menu. Enabled product pages also link to the editor.
2. Sign in or create an account. The studio returns after authentication.
3. Select a real purchasable product and option. Optionally upload one PNG/JPEG (25 MiB maximum, 60 MP maximum, minimum 100 pixels per side); a high-resolution transparent PNG is recommended. The minimum acceptance size is not a print-quality guarantee.
4. Drag, resize, rotate, fit/fill, center, repeat as a pattern, or change the print-area background. Arabic changes the controls and direction, while the physical artwork remains unmirrored. Source files are never changed. Switch the side panel between **Artwork** and **Text**. Add up to four text layers per product, with up to 120 characters/four lines per layer. Choose a bundled font, color, size, alignment and writing direction; position, rotate, duplicate or remove each layer. Enable **Drag selected text on the preview** for dragging/arrow-key movement. Text-only orders are supported; no upload is required. This is not a vector drawing editor.
5. Confirm the right to print the artwork and review the provisional preview. Subsequent placement/product changes clear the review checkbox.
6. Add the item to the bag. Continue with the same upload to create another product. Different designs and options have separate bag keys. Click a personalized bag image to reopen its saved layout; saving replaces that bag entry and preserves its quantity. Further edits create a new immutable saved design rather than changing any previous order.
7. Check out through the existing flow. The order remains `awaiting_payment`; no payment provider is enabled and no card details are collected. Artwork quality and supplier specifications must be confirmed manually before production. Do not print solely from the web preview.

Name the design and watch its save status. Changes are automatically saved to the signed-in account after a short pause (about 900 ms), with a **Save draft now** button. **My Designs** is available from the editor, account menu and mobile menu at `/en/my-designs` or `/ar/my-designs`. It contains editable drafts and immutable saved designs, with pagination. Continue a draft, make a copy, reuse a saved design, or confirm removal from the library. Removal archives the working draft; it does not delete files or change orders. Up to 100 active drafts are allowed per account.

Reload restores the requested/latest working draft. A device recovery copy keeps the latest 20 local working copies, including text/settings and opaque artwork IDs, not image bytes or credentials. If syncing fails, the editor explicitly says changes are only on this device and retries on reconnection. A new device can recover only changes successfully saved to the server. A page closed before its original upload finishes cannot recover that unuploaded file. If device storage is unavailable and the server save fails, the editor asks the customer to keep the page open and retry. Browser-local demo mode does not offer account autosave/library.

Draft revisions prevent a stale tab from overwriting another tab. A conflict pauses autosave and offers **Save a copy** or a confirmed **Reload saved version** that discards that tab’s unsynced edits. The preview-review checkbox must be confirmed before adding the item to the bag; draft restoration never approves an order. Originals are retained in private storage, including abandoned uploads; there is no automatic retention/deletion job.

## Privacy and production

- A signed-in account is required to upload and order personal artwork. Owners and administrators can view its bounded WebP previews. Other customers, anonymous visitors and unrelated artists cannot access the originals, metadata or private previews by knowing their IDs.
- Text is shaped by server-side Pango using the bundled, licensed TrueType fonts: Veelad Arabic Regular/Bold, DM Sans and Manrope. Arabic selected with a Latin family uses Veelad Arabic; this is stated beside the controls. Glyph PNGs are shared with the browser preview so browser/system font substitution does not change the lettering. Text IDs, font choices, Unicode, colors, placement, count and length are validated. Text is escaped as literal content, not HTML/Pango markup. The logical text renderer is `veelad-text-1`; retain the font binaries and renderer for existing orders.
- Private source files remain byte-for-byte originals in `UPLOAD_DIR` with mode `0600`; the server creates a separate photographic mockup. The artwork is not sent to an AI or third-party editing service.
- Saved `customer_designs` are immutable and owned by one user/product. IDs are content-derived for safe identical-save retries. State and checkout validate ownership, current product eligibility, category, options, quantities and stock. Checkout uses current server prices and snapshots the original, mockup and placement into each order line.
- Personal order lines have `artist_id: null` and `royalty_percent: 0`, so they do not enter an artist's order dashboard. Administrators see **Customer-designed item**, its preview, the original-file download and its specific placement-plan download in **Manage order**. **Download composed artwork (.png)** produces a flat transparent PNG containing both the placed image and text, without the photographed product or guides. It uses the product’s provisional canvas dimensions (or preview dimensions where the physical template is unknown), and the unbounded original as its image source. This export remains provisional and requires supplier review; it is not a certified print specification. The original upload remains separately downloadable and unchanged. Text-only items correctly have no original upload and never inherit the catalog artist’s artwork.
- Multiple personalized lines can refer to one product. Use the exact `line_id` when downloading an order placement plan; product ID alone is rejected if ambiguous. The plan includes the option, quantity and provisional template information. An administrator can still download an ordered design after the catalog changes or customization is disabled.
- These are provisional photographic preview templates, not supplier-certified product specifications. No physical printing or delivery integration is introduced.

## Migration, backups and rollback

`004-customer-designs.json` adds immutable `customer_designs`. `005-customer-design-drafts.json` adds indexed, revisioned `customer_design_drafts` for private working copies, without changing existing records. Staging startup applies additive migrations automatically; local/manual environments use `npm run migrate`. Any future production release requires its own reviewed migration and separate environment/secrets as described in the deployment documentation.

Encrypted backups now include both design tables and all private upload files. Older backups remain readable and restore with empty tables for features not yet present in that backup. The existing storage/backup/alert configuration remains necessary; adding this feature does not resolve any previously missing files or failed backup jobs. Verify a successful backup and restore rehearsal before enabling production.

To stop new custom orders, disable the checkbox on the affected products. Existing orders and production-file snapshots remain intact. For code rollback, keep migrations 004/005 and their data; do not drop it or delete any private artwork. An application predating text layers cannot reproduce text orders; preserve the current rendering/download code and bundled fonts for their fulfillment. A pre-feature application cannot correctly display or fulfill personal orders, so continue using the current administrator order/download handling for existing personal orders until they are fulfilled or cancelled. Preserve the database and upload directory together.

## Verification

Automated tests cover signed-in uploads, disabled-product rejection, ownership/rights/review enforcement, immutable save retries, separate designs on one SKU, price tampering, stock rollback, private previews after ordering, exact original bytes, line-specific order plans and encrypted backup/restore. Desktop and iPhone-sized Chromium workflows cover administrator enablement, customer registration return, upload reuse on a T-shirt and notebook, Arabic/English switching, saved bag editing, reload, unpaid checkout and administrator downloads. Native Safari and physical supplier samples require separate device/production validation.

Text/library tests additionally cover connected Arabic glyphs, literal markup, font/color/bounds validation, text-only previews and order originals, device recovery after failed saves/reload, cloud draft restoration, cross-user denial, concurrent revision conflicts, library copy/archive, exact order composition after later edits, and backup/restore of working revisions. No real payment or email delivery is enabled.

Customer-customized orders now initialize the preparation and final-proof workflow described in [Production workflow](PRODUCTION-WORKFLOW.md). Text/crop/opaque-background checks and touch controls are shared with artist previews.
